# 교회 행사용 스마트폰 조명 연출 시스템

관객이 QR로 접속해 자리를 등록하면, 운영자가 모든 폰의 화면 색(과 지원 기기의 플래시)을 원격 제어해
객석 전체를 하나의 전광판처럼 만듭니다. (한 사람 = 한 픽셀)

- 서버: Node.js + Express + Socket.IO, **DB 없이 JSON 파일 저장** (`data/layouts.json`, `data/patterns.json`)
- 관객 페이지 `/` · 운영자 페이지 `/admin.html` · 번호표 출력 `/print.html`

## 1. 로컬에서 테스트하기 (폰 2~3대)

```bash
cd lightshow
npm install
ADMIN_PASSWORD=1234 npm start
```

1. PC와 폰을 **같은 와이파이**에 연결합니다. PC의 IP를 확인합니다(예: `192.168.0.10`).
2. PC 브라우저에서 `http://localhost:3000/admin.html` → 비밀번호 로그인.
3. 폰에서 `http://192.168.0.10:3000/` 접속 → **참여하기** → 줄·좌석 선택 (폰마다 다른 자리, 한 대는 "건너뛰기").
4. 운영자 화면의 접속 현황 격자에서 초록 칸이 늘어나는지 확인하고, 십자가/하트/전체 ON/파도/글씨를 송출해 봅니다.

> 로컬(http)에서는 **카메라(플래시)와 화면 켜짐 유지(Wake Lock)** 가 브라우저 정책상 막힐 수 있습니다
> (`localhost`는 PC에서만 예외). 폰에서 플래시까지 시험하려면 HTTPS가 필요합니다 — 예: `npx localtunnel --port 3000`
> 또는 NAS 배포 후 확인. 화면 색 연출은 http에서도 동작합니다.
> iPhone(사파리)은 웹에서 플래시를 제어할 수 없어 화면 색만 사용합니다(정상).

자동 테스트: `npm test` (서버에 관리자 1 + 관객 3명을 붙여 인증·좌석·명령·안전 제한·배치 변경 등 30여 개 항목 검증)

## 2. 사용 흐름

**행사 전**
1. 운영자 → *좌석 배치 편집*: 줄 수, 기본 좌석 수, 줄별 좌석 수/정렬, 통로(칸 클릭), 범위 일괄 설정 → 저장.
   "본당/교육관/야외행사"처럼 여러 배치를 저장하고 행사 전에 **활성화**합니다.
   배치는 JSON으로 **내보내기/가져오기** 할 수 있습니다(저장된 패턴 포함).
2. *번호표 출력*으로 좌석 스티커를 인쇄(브라우저 인쇄 → PDF로 저장 가능). 번호는 통로를 건너뛰고 왼쪽부터 센 값이며, 관객 화면의 번호와 같습니다.
3. 관객 안내용 QR은 관객 주소(`https://내도메인.duckdns.org:포트/`)로 만드세요.

**행사 중**: 접속 현황으로 빈자리 확인 → 패턴 그리기/기본 패턴/글씨/효과 송출.

> ⚠ **활성 배치의 좌석 구조를 수정하거나 다른 배치를 활성화하면** 접속 중인 모든 관객에게 "자리를 다시 선택해 주세요"가 표시됩니다. 행사 도중에는 바꾸지 마세요.

## 3. 동작 원리

- 서버는 패턴 **전체**를 한 번에 브로드캐스트하고(`pat`: 팔레트 + 문자열 한 줄, 260칸 ≈ 300바이트), 각 폰이 자기 칸을 찾아 반응합니다.
- 모든 메시지에 활성 배치 ID(`lid`)가 포함되며, 다른 ID의 메시지는 무시됩니다.
- **동기화**: 서버가 `at = 서버시각 + LEAD_MS`를 붙여 보내고, 폰은 접속 때/20초마다 왕복 시간이 가장 짧은 샘플로 서버-폰 시계 차이를 보정해 `at`에 맞춰 실행합니다. 파도·글씨·깜빡임도 `at` 기준 절대시간으로 계산하므로 모든 폰이 같은 위상으로 움직이고, 중간에 접속/재접속한 폰도 바로 맞습니다.
- 건너뛰기 한 사람은 **전체 점등과 깜빡임**에만 참여합니다.
- 연결이 끊기면 자동 재접속하고, 좌석은 `localStorage`에 저장돼 다시 고르지 않습니다(배치 ID가 달라졌으면 재선택).
- 카카오톡/네이버/인스타 등 **내장 브라우저**를 감지하면 "크롬/사파리로 열기" 안내 화면이 나옵니다.

## 4. 안전 규칙 (광과민성 발작 예방)

- 깜빡임은 서버가 **초당 3회 이하**로 강제 제한합니다(UI 최대 3, 서버 클램프).
- 흐르는 글씨 속도는 칸당 170ms 이상, 파도는 칸당 100ms 이상으로 제한됩니다.
- 추가 안전장치: 폰 쪽에서도 어떤 명령이 와도 **각 폰의 켜짐 전환이 초당 3회를 넘지 못하게** 막습니다(플래시 포함).
- 기본 밝기 70% (운영자 슬라이더 10~100%).

## 5. Synology DS218 배포 (HTTPS + pm2)

DS218은 ARM64이며 이 프로젝트는 순수 JS라 별도 빌드가 필요 없습니다.

1. **패키지 센터**에서 *Node.js v18 이상*을 설치하고, SSH 접속을 켭니다(제어판 → 터미널 및 SNMP).
2. 프로젝트 폴더를 NAS에 복사합니다(예: `/volume1/apps/lightshow`).
3. ```bash
   cd /volume1/apps/lightshow
   npm install --omit=dev
   sudo npm install -g pm2
   ```
4. `ecosystem.config.js`에서 **`ADMIN_PASSWORD`를 변경**하고(필요하면 `PORT`도) 실행합니다.
   ```bash
   pm2 start ecosystem.config.js
   pm2 save
   pm2 startup     # 출력되는 명령을 그대로 실행하면 NAS 재부팅 후에도 자동 실행
   ```
5. **HTTPS 연결(카메라 권한 때문에 필수)** — 두 방법 중 하나:

   **A. DSM 역방향 프록시 (권장)** — 기존 duckdns 인증서를 그대로 사용
   - 제어판 → 로그인 포털 → 고급 → **역방향 프록시** → 생성
   - 소스: HTTPS / `내도메인.duckdns.org` / 포트 `8443`(원하는 새 포트)
   - 대상: HTTP / `localhost` / `3000`
   - **사용자 지정 헤더 → 만들기 → WebSocket** 을 눌러 헤더를 추가합니다(Socket.IO에 필요).
   - 공유기에서 `8443` 포트를 NAS로 포트포워딩하고, DSM 방화벽에서 허용합니다.
   - 접속: `https://내도메인.duckdns.org:8443/` (관객) · `/admin.html` (운영자)

   **B. Node가 직접 HTTPS** — `ecosystem.config.js`의 `SSL_CERT`, `SSL_KEY`에 인증서 경로를 지정하고
   `PORT`를 새 포트로 바꿔 포트포워딩합니다. DSM 인증서는 보통
   `/usr/syno/etc/certificate/_archive/<ID>/` 에 있으며 root만 읽을 수 있으므로, 이 폴더의 `fullchain.pem`/`privkey.pem`을
   pm2 실행 계정이 읽을 수 있는 위치에 복사해 두어야 합니다(갱신 시 다시 복사 필요 → A 방법이 더 편합니다).
6. 업데이트: 파일 교체 후 `pm2 restart church-lightshow`. 로그: `pm2 logs church-lightshow`.
7. 데이터 백업: `data/` 폴더(`layouts.json`, `patterns.json`)만 복사하면 됩니다.

### 환경변수
| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 서버 포트 |
| `ADMIN_PASSWORD` | church1234 | 운영자 비밀번호 (반드시 변경) |
| `LEAD_MS` | 600 | 명령 예약 지연(ms). 수백 명 동시 접속·약한 와이파이면 800~1000 |
| `DATA_DIR` | ./data | JSON 저장 위치 |
| `SSL_CERT`, `SSL_KEY` | 없음 | 지정하면 서버가 직접 HTTPS |

## 6. 현장 팁

- 행사장 와이파이/LTE 혼재 시 동기 오차는 보통 수십 ms 이내입니다. 파도가 어긋나 보이면 `LEAD_MS`를 늘리세요.
- 한 번에 수백 대가 접속해도 메시지는 수백 바이트이고, 글씨(흐르는 글씨)만 수 KB입니다(압축 전송).
- 글씨는 운영자 PC의 한글 폰트(맑은 고딕 등)를 현재 배치 **높이**에 맞춰 픽셀화합니다. 줄 수가 적은 배치(10줄 미만)는 한글이 뭉개질 수 있습니다.
- iPhone은 웹에서 플래시 제어가 불가능해 화면 색만 사용합니다. Android Chrome에서 플래시가 동작합니다.
